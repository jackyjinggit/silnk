01核心判断（需要现在拍板的事）

先给结论，再给依据。

推荐：不靠"铺设备卖打印页"，靠「1 个自营样板点位 + 软件与增值变现」两条腿，6 个月内把月毛利做到 1 万。
  • 事实校园打印单价被制度性锁死在 0.1~0.15 元/页，且多为黑白（北外图书馆黑白单面 0.1 元、中国海洋大学 0.15 元/张）。
  • 事实单张硬成本约 0.05 元（纸 0.03 + 碳粉与维修 0.02），单面毛利 ~0.05 元。
  • 估算纯打印要月净利 1 万，需约 20 万页/月（≈日 7000 页）——单点位不现实。
  • 事实经营 6 年的校园复印店实证：复印只是引流，利润来自增值服务（模板、论文、装订、彩印、设计排版）。
  • 建议竞争位选「确定性交付 + 增值 + AI 助手」，不做泛社会低价云打印（对手已到 5 分/面包邮，采用工业级设备 + AI 拼版）。

明确不做：不铺多个低效点位；不做彩色大幅面 / 广告物料；不做依赖 GPU 的本地大模型。

02公司定位与生态位

维度结论
公司思印客 Silnk（已注册），软硬一体的「校园文档交付终端 + 打印数字化系统」
团队4 人：33 岁 AI 架构师、18 岁硬件/服务器、12 岁全栈、16 岁战略/运营
硬约束服务器无显卡 → AI 全部走云端 API，本地只跑业务、队列、PDF 渲染
稀缺资产自有软件（下单/队列/计价/告警/内容审核/自助客户端）、2 台打印机 + ESP32-S3、1 个在谈校园点位
关键依赖学校场地审批、接电接网、纸张耗材供应、第三方 AI / 支付 / 短信 API

生态位：不站在"最便宜的打印"一端，也不站在"纯人工图文店"一端，而是占中间的「确定性交付 + 增值 + AI 助手」——批量、急件、有格式要求的学生与班级，最愿意为"省时间、别出错"买单。

03需求信号（大学场景）

  • 事实图书馆自助文印 0.1~0.15 元/页（多为黑白）；校外图文店 0.5 元/面；校内低价自助店可低至 0.06 元/面；云打印最低 0.05 元/面、包邮次日达。
  • 行为学生需求高频、批量、临时急用；简历/合同/证件等敏感件偏好当面打印。
  • 判断一部分人只看"最低价"，另一部分人要"立刻拿到 + 能现场改格式"。→ 我们打交付确定性与增值，不打最低价。
  • 待校准目标点位真实日订单量、复购率、增值渗透率（试运营前均为未知）。

  • 软件订阅边际成本 ≈ 1 台无显卡服务器可承载，毛利近 90%，是最健康的一块。

05成本结构（无显卡约束下的技术选型）

AI：全部走云端 API

DeepSeek 做指令/文案，GLM-5.3-Flash 做印前视觉审核。本地只跑业务、队列、PDF 渲染与规则缓存，不需要 GPU。

固定成本

场地分成 / 电费、设备折旧、服务器、短信与支付手续费。

变动成本

纸、碳粉、装订耗材、AI API token。

规模效应

软件与 AI 边际成本趋近于 0，是"1 万"里可复制的部分；打印是引流，不承担利润。

07战略选项与取舍

A 自营铺点

重资产、见效慢，但能验证真实单位经济。

B 软件赋能 / 订阅

轻、可复制、毛利高。

C 维持现状

只保留黑客松 demo，无收入 —— 作为基线对照。

推荐组合

A（1 个样板点）+ B（同步卖软件）为主，C 作基线；明确不做 D：泛云打印低价竞争。

10实施步骤（30 / 60 / 90 天）

第 1~30 天 · 立地基

  • 法务与资质：公司资质、商标（第 40 / 9 / 35 类）。
  • 场地：与德科技术学院确认分成、接电接网、责任划分，拿书面协议。
  • 设备就位：打印机 + ESP32-S3 心跳 + Linux 客户端，跑通自助下单 → 支付 → 出纸 → 取件。
  • 记账：每单记录页数 / 成本 / 收入，建立真实单位经济基线。

第 31~60 天 · 跑数据

  • 上线增值价目：装订（胶装/骑马订/覆膜）、彩印、封面、排版。
  • 校准单位经济，砍掉亏损类目。
  • 系统 SaaS 化，给 2~3 家打印点免费试用换反馈与案例。

第 61~90 天 · 见结果

  • 签约 3~8 家订阅，发布 AI 增值。
  • 得出"月毛利是否达 1 万"的阶段结论。
  • 决策：是否复制第 2 个点位。
指标树：命题 → 月毛利 1 万；领先指标 = 日订单数、复购率、增值渗透率；驱动 = 点位覆盖、SaaS 家数、AI 单量；护栏 = 客诉率、耗材成本/页、合规事件 0。

11结论与近期决策

  • 现在要批准：① 德科技术学院点位落地；② 系统 SaaS 化投入；③ 3 家打印点试点。
  • 观察什么：日订单量、增值渗透率、SaaS 付费与续费。
  • 下一步：先用 1 个点位验证真实单位经济，再谈复制；验证前不铺第 2 个点位、不做彩色大幅面。

签约与收款（合规）：合同、收款、对外承诺由 33 岁（主）与 18 岁（次）落签；12 / 16 岁只做研发与内容，监护人书面同意，不签劳动合同、不参与签约与收款。

合兵点（四条线共用的接口约定）

  • 唯一计价源 = 后端 pay.py，前端不得自行定价 —— 避免四条线价格不一致。
  • 每天 21:00 五分钟卡点同步（沿用项目规则），只同步卡点，不汇报进度。
  • 每周一张指标表：四条线各报 2 个数（见第八节指标树）。

分头但不分家：主线 owner 决自己的日常事；跨线接口（下单 → 出纸 → 增值 → 交付）出问题找对应 owner，30 分钟定不下来就升级给 33 岁。

Must 阶段的起跑（第一周四条线各出一个可验证结果）

  • 33 岁：盯场地书面许可（分成/接电接网/责任）。
  • 18 岁：设备到位，打印机 + 客户端 + ESP32 心跳跑起来。
  • 12 岁：自助下单 → 支付 → 取件闭环跑通。
  • 16 岁：摸清目标点位真实日流量（蹲点计数），拿到定价第一手数据。
