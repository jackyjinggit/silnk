## 一、合规基线（三条硬规则）

1. **基线冻结**：演示日开始第一件事，给当前 main 打标签并推到远端。
   ```
   git tag -a baseline-30 -m "赛前基线：核心闭环 30%"
   git push origin baseline-30
   ```
   此后所有提交都在该标签之后，评委可用 `git diff baseline-30..main --stat` 自行核对增量。
2. **不改历史**：不使用 `git commit --date` 回填时间、不 rebase 改写已有提交、不 force push。提交时间必须是真实发生时间。
3. **一条提交一件事**：单条提交控制在 3–6 个文件，附一条测试或一张验收截图。不把一天的工作压成一条大提交，也不把一条功能拆成十条空提交。

**为什么这样就不算作弊**：基线是赛前真实产物且已公开在远端；70% 的增量是现场真实写、真实跑、真实出纸的；时间戳、文件顺序、提交之间的因果（后一条依赖前一条的接口）全部自洽。

## 四、涂鸦 T5AI + LCD 方案（权重 24，主线）

**角色**：打印机旁的取件屏与语音叫号终端，解决「不知道去哪台机、不知道好了没」。

**链路**：
```
T5AI 板 ——HTTP 轮询——> 后端 /api/display/{device_id}/state
                        <—— 队列 / 纸量 / 告警 / 取件码 / 订单状态
```

**屏幕三态**（评委 10 秒能看懂）：
- 空闲：大字「可打印」+ 当前单价 + 纸量
- 忙：当前任务缩略信息 + 排队人数
- 可取件：超大字号取件码 + 闪烁提示 + 语音播报「尾号 XXXX 请取件」

**风险与备选（重要）**：T5AI 现场配网耗时不可控。若 11:00 前未联通 WiFi，立即切**串口方案**：板子 USB 接工控机，由工控机上的 Python 进程推数据，屏幕只负责渲染。串口方案 20 分钟可上屏，功能演示不受影响，图纸上注明「正式版走 WiFi，现场为稳定演示走串口」。

## 五、地瓜 RDK X5 方案（权重 16，加分项）

**角色**：出纸口边缘视觉，判断是否真的出纸、是否卡纸，解决「系统显示已打印但实际没出纸」。

**算法**：不现场训练模型。摄像头对准出纸口固定 ROI，帧差 + 亮度突变判定纸面出现，连续 90 秒无事件且订单处于 printing 则上报异常。X5 的 NPU 只作为后续演进说明，不宣称已使用。

**接口**：
```
POST /api/edge/{device_id}/eject   { "event": "sheet_out", "ts": 1690000000, "confidence": 0.82 }
```

**与告警联动**：新增 R6「出纸异常」——心跳正常 + 订单 printing 超 5 分钟 + 无出纸事件。与既有运维 agent 分档保持一致：物理类只上报留痕，不自动下发指令。

**风险与备选**：若光照导致误判，退化为「只做事件上报 + 人工确认」，R6 改为建议级提示，不阻塞出纸。

### 6.4 每人开工 / 收工清单

开工三件事：`git pull` 确认最新 → 看板上认领本时段任务 → 确认自己那条链路能跑通再动手。
收工三件事：`pytest` 或本地跑通 → `git push` → 在群里发一句「完成了什么 / 卡在哪」。

### 6.5 三条防超时规则

1. **10 秒规则**：任何功能如果不能在演示的 10 秒内被评委看见，就不做。
2. **不做多机型适配**：只用现场两台打印机，不写型号兼容分支。
3. **报错只打日志**：不写异常兜底 UI，不在非主线路径上花时间。
