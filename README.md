# 印立方 printpilot

> 自助打印三合一管理端：打印 + UPS + 监控，一个面板看全部，主动告警代替被动巡检

## 定位

- **中文名**：印立方（蒋平拍板）
- **英文名 / 仓库名**：printpilot（蒋平拍板）
- **场景**：自助打印运营商（打印店 / 政务大厅 / 校园驿站）
- **卖点**：降本 + 安全 + 便捷
- **基座**：[自助印 233kun/self-service-printer](https://github.com/233kun/self-service-printer)（MIT 协议，商用友好）

## 解决的真问题（客户实证）

| # | 痛点 | 来源 |
|---|---|---|
| 1 | 纸量上报不准 → 缺纸没及时发现 → 客户投诉 | 群组反馈 |
| 2 | 断电 / 离线无通知 → 停机没人知道 | 群组反馈 |
| 3 | 取货口无管理 → 打印顺序被搞乱 → 恶意退款 | 群组反馈（门磁方案）|
| 4 | 打印 + UPS + 监控 **三个管理端**分开看，通知不及时 | 群组反馈 |

## 5 条告警（产品的魂）

| # | 触发 | 通知 | 数据源 |
|---|---|---|---|
| R1 | 估算剩余纸量 ≤ 10% | 补纸预警：X 号机剩余 ≤10%，请补纸 | CUPS job counter 软件估算（蒋平拍板：计数剩余 10%）|
| R2 | 打印机离线 / 断电 | 停机告警：X 号机离线 | 打印机心跳 |
| R3 | UPS 市电断开 | 市电断开：UPS 供电中，剩余 X 分钟 | UPS（NUT 协议）|
| R4 | 门磁开但任务未完 | 取件异常：有未完成取件 | 门磁 GPIO |
| R5 | 取件顺序不符 | 顺序异常：第 N 件被跳过 | 门磁 + 任务队列 |

> **硬件现实**：普通打印机不带纸量感应，只能通过打印量计算。即便是商业机型也只能感应满纸 / 少纸 / 缺纸。R1 采用软件估算（累计打印张数 ÷ 纸盒容量），**阈值 = 估算剩余 ≤ 10%**（蒋平拍板），demo 时说明是估算不是硬件感知。

## 架构

```
用户手机 ──扫码──► 前端(Vue) ──► 后端(FastAPI+SQLite) ──► 打印机端(小工控机 Ubuntu)
                                      │                        │
                                      │ 5 秒轮询               ▼ CUPS 调 USB
                                      └───────► /printer/jobs ─► 真机打印
                                                               │
                                                        G3800 / M1005
```

**任务流转**：手机扫码下单 → 后端入队 → 工控机 5 秒轮询取任务 → CUPS 打印 → 回传状态。

## MVP 功能（5 项）

1. 打印机列表页（跨品牌状态聚合）
2. 打印任务提交（选文件 → 选机 → 提交）
3. 任务状态跟踪（队列 / 打印中 / 完成 / 失败）
4. 成本看板（月度张数 / 估算成本 / 趋势）
5. 价格对比页（我们 vs PaperCut / PrinterLogic）

## 技术栈

| 层 | 选型 |
|---|---|
| 前端 | Vue / uni-app（沿用自助印基座）|
| 后端 | FastAPI + SQLite |
| 打印机端 | 小工控机 + Ubuntu Server 22.04 + CUPS |
| 驱动 | G3800: cnijfilter2（Canon）/ M1005: hplip + hp-plugin（HP）|
| 网络 | 4G 模块 + SIM 卡（不依赖现场 WiFi）|
| 告警推送 | 企业微信 Webhook |
