## 一、测试准备

### 1.1 环境

| 项目 | 要求 |
| --- | --- |
| 平台地址 | `https://silnk.cn`（或测试服地址） |
| 平台密钥 | 后端环境变量 `SECRET_KEY`，用于设备注册、心跳、任务接口 |
| 租户 | 建议新建专用测试租户 `qa-tenant`，避免污染真实数据 |
| 打印机 | 1 台真实打印机；无硬件时可用 curl 模拟设备侧请求 |
| 客户端 | `client/`，已安装 cups-client、cups-ipp-utils；Linux 工控机或 Windows |
| 工具 | 浏览器、curl、平台管理端账号 |

### 1.2 客户端环境变量

```
SERVER_HOST=https://silnk.cn
SECRET_KEY=<平台 SECRET_KEY>
PRINTER_DEVICE_ID=qa-01
TENANT_ID=qa-tenant
```

说明：
- `SECRET_KEY` 是平台密钥，不是租户密钥；租户密钥只用于租户控制台。
- 同一租户多台机器，`PRINTER_DEVICE_ID` 必须不同，否则心跳与任务互相覆盖。

### 1.3 优先级

- P0：接入主链路，失败即不可用。
- P1：隔离、配额、计费、告警等关键正确性。
- P2：异常恢复、边界与展示。

## 二、注册与鉴权

| 编号 | 优先级 | 用例 | 步骤 / 输入 | 预期结果 |
| --- | --- | --- | --- | --- |
| A-01 | P0 | 首次注册成功 | 客户端启动，或 `POST /api/device/register` 携带平台密钥与 `device_id=qa-01`、`tenant_id=qa-tenant` | 返回 `code=200`、`message=success`；平台端「设备」页出现 qa-01，归属 qa-tenant |
| A-02 | P0 | 重复注册幂等 | 同一 `device_id` 再次注册，修改 `name` 或 `paper_capacity` | 不新建重复设备；字段被更新；不触发配额报错 |
| A-03 | P0 | 缺少密钥 | 不带 `Authorization` 调用注册接口 | 返回 403，不创建设备 |
| A-04 | P0 | 错误密钥 | `Authorization: Bearer wrong-key` | 返回 403，不创建设备 |
| A-05 | P1 | 租户密钥越权 | 用租户密钥 `sk_...` 调用注册接口 | 返回 403（merchant key required），不创建设备 |
| A-06 | P1 | 运维密钥越权 | 用 `OPS_KEY` 调用注册接口 | 返回 403，不创建设备 |
| A-07 | P1 | 设备未上报打印机队列 | `printers` 传空或不传 | 注册成功；管理端显示为空队列，不报错 |
| A-08 | P1 | 设备能力上报 | `supports_color=false`、`supports_duplex=false` | 平台端设备详情显示对应能力；下单双面会被拦截（见 E 组） |
| A-09 | P1 | 心跳自动补注册？ | 未注册的 `device_id` 直接发心跳 | 返回 `message=device not found`，不会自动创建设备 |
| A-10 | P2 | 超长/特殊字符设备 ID | `device_id` 含空格或中文 | 不建议使用；记录实际表现，作为命名规范依据 |
| A-11 | P2 | 注册后归属修正 | 已注册设备心跳携带新的 `tenant_id` | 设备归属更新为新租户；原租户列表不再显示它 |
| A-12 | P2 | 两台机器同设备 ID | 两台机器都设成 `qa-01` 并发心跳 | 心跳互相覆盖、任务可能串单；记录为部署错误，必须在接入检查中排除 |

## 二点五、零配置接入（本轮新增）

| Z-04 | P0 | 批准后点位信息落库 | 批准时填地址与经纬度 | 设备详情中地址、营业时间、经纬度与填写一致；留空时不报错，只是不参与附近推荐 |

| Z-13 | P1 | 老部署兼容 | 环境变量仍有 `SECRET_KEY`，无 `config.json` | 客户端按老方式启动，注册与心跳正常，行为不变 |
| Z-14 | P2 | 重新配对 | 已接入机器点「重新配对」 | 旧配置备份为 `config.json.bak`，界面回到未接入，可重新申请 |

## 十一、端到端冒烟（API 级，可直接执行）

把下面变量替换成测试环境值后按顺序执行：

```bash
BASE=https://silnk.cn
KEY=<平台 SECRET_KEY>
TID=qa-tenant
DID=qa-01

# 1. 注册（新设备会校验租户状态与上限）
curl -s -X POST "$BASE/api/device/register" \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d "{\"device_id\":\"$DID\",\"name\":\"QA打印机\",\"tenant_id\":\"$TID\",\"paper_capacity\":250}"

# 2. 心跳
curl -s -X POST "$BASE/api/device/heartbeat" \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d "{\"device_id\":\"$DID\",\"status\":\"online\",\"tenant_id\":\"$TID\"}"

# 3. 拉取任务
curl -s "$BASE/printer/jobs?device_id=$DID" -H "Authorization: Bearer $KEY"

# 4. 上报开始打印
curl -s -X POST "$BASE/printer/job/state" \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
```

## 十三、已知边界（验收时不要按「已实现」判定）

- 彩色能力目前没有下单硬拦截，只有双面能力有硬拦截。
- 旧版客户端不带 `device_id` 拉取任务时会拿到队首订单，无法做设备隔离。
- 设备心跳不校验租户是否停用；停用只影响新订单与用户端展示，心跳仍记录用于排查。
- 资料库仍是平台级公共库，不按租户隔离。
- 支付宝自动分账、自动续费、页面自助重置租户密钥均未实现。
