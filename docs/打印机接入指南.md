# 思印客 Silnk · 打印机接入指南

> 适用版本：2026-10 · 客户端 `client/`（Windows / Linux）
> 目标：把一台真实打印机接到 https://silnk.cn，能收单、能出纸、状态可查。

---

## 一、支持范围

| 项目 | 支持情况 |
|---|---|
| 操作系统 | Linux（工控机直装或 Docker）、Windows 10/11 |
| 打印机接口 | USB 直连、网络打印机（IPP / 局域网） |
| 打印机型号 | **不做白名单**。只要操作系统能驱动、CUPS 能建队列，就能接 |
| 已验证机型 | 佳能 G3800（喷墨、彩色、无自动双面）、HP Smart Tank 510 |
| 出纸链路 | Linux 本机 CUPS 队列优先用 `lp` 提交，远程 IPP 队列用 `ipptool`；Windows 用 SumatraPDF 静默打印。命令成功只代表任务被队列接受，不等于逐页物理出纸 |

型号只用于展示与能力判断，不影响能否接入。

---

## 二、接入前准备

向系统管理员（或管理端 `/admin/`）确认四件事：

1. **后端地址**：正式环境为 `https://silnk.cn`
2. **SECRET_KEY**：与后端一致的密钥（服务器环境变量，不在代码里）
3. **设备 ID**：每台打印机唯一，例如 `g3800-01`、`g3800-02`
   - 不填会回退为 `printer-001`，**多台机器会互相覆盖心跳**
4. **纸盒容量**：默认 250 张，按实际纸盒填写

## 三、Linux 工控机接入（推荐）

### 3.1 安装系统依赖

```bash
# cups：打印服务
# cups-client：提供 lpstat / lpoptions（客户端自动识别型号与能力要用）
# cups-ipp-utils：提供 ipptool（出纸链路必须）
sudo apt-get update
sudo apt-get install -y cups cups-client cups-ipp-utils python3
sudo systemctl enable --now cups
```

CentOS / Rocky 对应包名为 `cups`、`cups-client`、`cups-ipp-utils`（`dnf install`）。

### 3.2 安装打印机驱动并建队列

**佳能 G3800**：优先安装 Canon 官方 G3000 series Linux 驱动；装不上时改用 Gutenprint：

```bash
sudo apt-get install -y printer-driver-gutenprint
```

建队列可以用图形界面（`http://localhost:631` → Administration → Add Printer），
也可以用命令行：

```bash
# 查看 USB 设备
lpinfo -v | grep -i usb
# 建队列（URI 与驱动按实际输出替换）
sudo lpadmin -p Canon_G3800_series -E -v "usb://Canon/G3800%20series" -m everywhere
sudo cupsenable Canon_G3800_series
sudo cupsaccept Canon_G3800_series
```

> `-m everywhere` 走 IPP Everywhere 自动匹配驱动，多数现代打印机可用；
> 不支持时改用 `lpinfo -m | grep -i g3800` 找到 PPD 名称替换。

### 3.3 确认队列名

```bash
lpstat -p
# printer Canon_G3800_series is idle.  enabled since ...
```

记下队列名，下一步要填进 `PRINTER_URL`。

### 3.4 配置环境变量

`client/setting.py` 优先读环境变量，不需要改任何文件：

```bash
export SERVER_HOST=https://silnk.cn
export SECRET_KEY=<与后端一致的密钥>
export PRINTER_URL=ipp://localhost:631/printers/Canon_G3800_series
export PRINTER_DEVICE_ID=g3800-01
export PRINTER_PAPER_CAPACITY=250
```

可选变量：

| 变量 | 作用 | 默认 |
|---|---|---|
| `PRINTER_DISPLAY_NAME` | 管理端显示名，如「图书馆一楼 G3800」 | 空（保留管理端设置） |
| `PRINTER_MODEL` | 手动覆盖识别出的型号 | 自动识别 |
| `PRINT_MAX_RETRIES` | 单份失败重试次数 | 2（合计 3 次） |
| `PRINT_RETRY_DELAY` | 重试间隔（秒） | 3 |

### 3.5 启动

```bash
cd client
python3 main.py
```

启动后会看到：

- `Register printer success`：设备已注册
- `Heartbeat reported`：每 25 秒一次心跳
- 60 秒无心跳，后端判定离线并触发 R2 告警

长期运行建议用 systemd：

```ini
# /etc/systemd/system/silnk-printer.service
[Unit]
Description=Silnk printer client
After=network.target cups.service

[Service]
WorkingDirectory=/opt/silnk-client
Environment=SERVER_HOST=https://silnk.cn
Environment=SECRET_KEY=<密钥>
Environment=PRINTER_URL=ipp://localhost:631/printers/Canon_G3800_series
Environment=PRINTER_DEVICE_ID=g3800-01
ExecStart=/usr/bin/python3 main.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now silnk-printer
```

### 3.6 Docker 方式

```bash
cd docker-compose/client
# 编辑 docker-compose.yml 填入环境变量
docker compose build
docker compose up -d
```

镜像已包含 `cups-client` 与 `cups-ipp-utils`，无需额外安装。

## 四、Windows 零配置接入（推荐，本轮新增）

不用改 bat、不用设 `SECRET_KEY` / `PRINTER_DEVICE_ID`，现场只需三步。

### 4.1 前置条件

1. 安装打印机官方驱动，在「控制面板 → 设备和打印机」确认队列名
2. 安装 SumatraPDF（出纸用）
3. Python 3.10+（Windows 安装包自带 tkinter）

### 4.2 运行图形向导

```bat
cd client
python setup_gui.py
```

1. 服务器地址填 `https://silnk.cn`
2. 选择本机打印机队列（点「刷新」重新扫描）
3. 纸盒容量按实际填写（默认 250）
4. 点「开始接入」，窗口会显示 4 位接入码（30 分钟内有效）

### 4.3 管理端批准

1. 打开 `/admin/devices.html`，顶部「待接入设备」会出现这台机器的主机名、队列与接入码
2. 点「批准」，填写点位名称、租户、地址、营业时间；经纬度可留空（留空的设备暂不参与附近推荐）
3. 批准后客户端自动领取设备令牌，8 秒内设备状态变为在线

### 4.4 自动生成的配置

`client/config.json`：

```json
{
  "server_host": "https://silnk.cn",
  "device_id": "dev-1a2b3c4d",
  "token": "设备专属令牌",
  "printer_name": "Canon G3800 series",
  "printer_display_name": "print-pc-01",
  "paper_capacity": 250
}
```

- 令牌只存服务端哈希，终端泄露后可让管理端删除设备重新配对
- 换机器或重装：点向导里的「重新配对」，旧配置会备份为 `config.json.bak`
- 老部署仍然兼容：只要环境变量里有 `SECRET_KEY`，客户端照旧按老方式启动

## 五、Windows 手动配置（老方式）

1. 安装打印机官方驱动，在「控制面板 → 设备和打印机」确认队列名
2. 下载 SumatraPDF（出纸用）
3. 复制配置模板并修改：

```bat
copy client\start_win.bat.example client\start_win.bat
```

```bat
set SERVER_HOST=https://silnk.cn
set SECRET_KEY=<密钥>
set PRINTER_DEVICE_ID=win-01
set PRINTER_NAME=Canon G3800 series
set PRINTER_PAPER_CAPACITY=250
client\start_win.bat
```

可选：

| 变量 | 作用 |
|---|---|
| `SUMATRAPDF_PATH` | SumatraPDF.exe 路径，不填自动探测 |
| `PRINTER_FORCE_SIMPLEX=1` | 强制单面。手动双面打印机在无人值守时会弹「翻面后继续」卡住，建议开 |

> `PRINTER_NAME` 留空时打到系统默认打印机。多台机器务必设置不同的 `PRINTER_DEVICE_ID`。

## 六、管理端登记与验证

1. 打开 `https://silnk.cn/admin/devices.html`，用商家密钥登录
2. 点「新增设备」：客户端已上报的队列会出现在列表里，可一键填入名称/驱动/端口
3. 填写或确认：
   - 纸盒容量（张）
   - 彩色能力（G3800 勾选）
   - 双面能力（G3800 **不要勾选**）
4. 点「打印测试页」，确认纸上出现「思印客 · 打印测试页」
5. 用手机打开 https://silnk.cn，登录后上传一个 PDF，选这台打印机下单
6. 确认出纸、手机上订单详情里的取件码、订单状态变为已完成（纸上不印取件码）
7. 可选验证「定时打印」：下单时勾选「定时出纸」并选 1~2 分钟后，订单先显示「已预约」；
   到点后后台自动放行，订单转「已支付」→「打印中」→「待取件」；未到点前可在订单详情点「取消预约」。

**能力字段的规则**：客户端首次注册时自动写入彩色/双面能力；
管理端手动改过之后，客户端不再覆盖。这样设备重启不会冲掉人工设置。

## 六、佳能 G3800 专项说明

| 项目 | 值 |
|---|---|
| 类型 | 喷墨一体机（打印/复印/扫描） |
| 彩色 | 支持 |
| 自动双面 | **不支持** |
| 纸张 | A4 / A5 / Letter / 照片纸等 |
| 连接 | USB |
| 自动识别结果 | 型号 `Canon G3800 series`、彩色 = 是、自动双面 = 否 |

两个必须注意的点：

1. **不要勾选双面能力**。G3800 没有自动双面，勾了会让用户按双面价（0.5 元/张）付费却单面出纸。
   现在后端已加保护：设备标记为不支持双面时，双面订单会被拒绝并提示
   「所选打印机不支持自动双面，请改为单面或换一台打印机」。
2. **不要用 `PRINTER_FORCE_SIMPLEX`**（那是 Windows 专用），Linux 下双面能力由 PPD 判断。

## 七、多台打印机

- 每台设置不同的 `PRINTER_DEVICE_ID`，否则心跳互相覆盖、订单可能被错误设备认领
- 客户端的 `PRINTER_NAME` / `PRINTER_URL` 指向本机队列，不要指向别的机器
- 管理端按设备 ID 分别设置纸量、位置、能力
- 未指定设备的订单由第一台取任务的设备认领

## 八、常见问题

**Q：客户端显示注册成功，但管理端设备列表没有？**
检查 `SECRET_KEY` 是否与后端一致；管理端刷新页面。

**Q：设备一直显示离线？**
心跳间隔 25 秒、超时 60 秒。检查客户端进程是否存活、服务器是否可达
（`curl -I https://silnk.cn/healthz`）。

**Q：能进队列但不出纸？**
- Linux：`lpstat -p` 看队列是否 enabled；`ipptool -tv $PRINTER_URL ipp_files/print_ticket_attributes.ipp` 手动测
- Windows：确认 `PRINTER_NAME` 与控制面板里的名字完全一致（含空格与大小写）

**Q：识别到的型号是空的？**
Linux 下 `lpstat -l -p <队列>` 的 `Description:` 为空时会这样。
可以用 `PRINTER_MODEL=Canon G3800 series` 手动覆盖，只影响展示。

**Q：扫描件能打印吗？**
能。扫描件只是无法做 OCR 格式检查与本地隐私识别，打印不受影响。

**Q：打印失败会重复出纸吗？**
可能。失败可能发生在已出部分纸之后，客户端会重试 2 次，日志会记录；
介意的话可以在管理端把重试次数设为 0（`PRINT_MAX_RETRIES=0`）。

## 九、安全提醒

- `SECRET_KEY` 只放环境变量或 systemd 配置，不要写进代码、不要提交 Git
- 打印机客户端只需要访问后端 `/api/device/*`、`/printer/*` 接口，不需要开放入站端口
- 工控机建议只跑打印客户端，不装无关软件；USB 口物理隔离
- 管理端密钥（`SECRET_KEY`）与运维密钥（`OPS_KEY`）权限不同，日常运维用 `OPS_KEY`

## 十、显示终端与边缘终端（已有实现，现场验收未完成）

> 当前工作区已有显示状态接口、设备鉴权与限流、串口桥接、取件确认接口、X5 出纸事件上报、R6 出纸异常告警和管理端显示页。T5 触摸固件已烧录，但实际点击闭环未验证；X5 在线基准需重建；用户照片已部署，完整实拍未验收。详细状态见 [现场拓展计划_30到70.md](./现场拓展计划_30到70.md)。

现场新增两类外设，均**不需要开放入站端口**，由终端主动访问后端：

| 终端 | 硬件 | 连接方式 | 作用 |
|---|---|---|---|
| 取件屏 | 涂鸦 T5AI + LCD | USB 串口接工控机，由桥接进程推数据 | 状态显示、断网保留末帧和取件确认协议已有实现；触摸实际点击未验证，语音叫号未验收 |
| 出纸检测 | 地瓜 RDK X5 + USB 摄像头 | 本地帧差判定后 HTTP 上报 | 事件/照片接口和部署已有；在线检测基准需重建，完整实拍未验收；R6 出纸异常已实现（printing 超 5 分钟且无事件时告警，事件到达自动关窗），已于 10/24 22:55 部署 silnk.cn |

**接入约束**

- 取件屏与打印机客户端共用同一台工控机时，串口设备号（如 `/dev/ttyUSB0`）需固定，建议用 udev 规则绑定，避免重启后变化
- 显示终端复用现有设备令牌（`device_tokens`），不新增明文密钥；令牌按设备 ID 隔离
- 出纸检测只上报事件，不做判责；R6 与既有物理类告警一致，仅上报留痕，不自动下发指令
- 无出纸事件时不得伪造；CUPS 提交成功不能等同物理出纸，R6 以「printing 超 5 分钟且无事件」作为判定依据
