# 演示录屏脚本（主线：交付证据链）

> 成片 3 分 40 秒—4 分钟。主线只讲一件事：别的自助打印只保证「纸出来了」，思印客保证「打对了、拿对了、删干净了」。
> 其余功能（多租户、拼单、价格对比、7 套模板逐个展示、技术栈罗列）一律不占视频时长，留给答辩问答。

## 一、镜头配比

| 段落 | 时长 | 占比 | 负责什么 |
| --- | --- | --- | --- |
| 开场亏钱场景 | 0:00–0:40 | 约 18% | 让评委看见钱和纸正在被浪费 |
| 中段 Web 主体 | 0:40–2:40 | 约 55% | 体检拦截、修复、真实计价、隐私打码，用数字说话 |
| 高潮硬件证据 | 2:40–3:20 | 约 18% | T5 取件确认 + X5 出纸照片，证明交付可追溯 |
| 收尾 | 3:20–3:40 | 约 9% | 删除记录 + 一句边界说明 |

硬件只占不到两成，且排在 Web 之后：即使现场硬件掉链子，主线依然完整，不会整段崩。

## 二、逐段脚本

### 0:00–0:40　开场：先让他们看到在亏钱

画面：不做任何登录页铺垫，直接开一份 12 页文档的上传页，把「单面黑白」勾好。

口播：一份 12 页的文档，看上去就是普通黑白单面。实际上里面有 3 页彩色，选错色彩，每一页多花 0.5 元；又因为页数是奇数，双面打印会多出一张空白背面。这两件事，传统流程要到纸吐出来才发现——钱花了，纸也废了。

要点：这段不要念参数，只念后果。录制前用实际样例重新算一遍金额和废纸张数，把脚本里的示例数字换成真实值，口播照着真实值说。

数据要求：画面上要能看见「预估金额」和「彩色页 3 页」这两个元素，评委会自己算账。

### 0:40–1:20　中段之一：体检拦截

画面：点「开始体检」，体检结果页出现彩色页不符、双面奇数页、页边距过窄三条提示。

口播：问题在下单前就暴露，不是出纸之后。这三条提示只提醒、不阻断，用户自己决定要不要改。

数据要求：体检得分要真实读出来（样例文档实测 97 分），不要口头编一个分数。

### 1:20–1:50　中段之二：一键修复

画面：点「一键修复」，得分从 97 变 100，问题项逐个变绿。

口播：一键修复只做内容级操作——删空白页、插封面、双面配对；不动页边距、不擅自加页码，因为改版式会改坏用户的原文档。

数据要求：修复前后得分对比必须同屏可见。

### 1:50–2:20　中段之三：彩色按真实颜色计价

画面：切到彩色计价，金额实时变化；下单页显示最终应付与耗纸张数。

口播：彩色页按彩色价、黑白页按黑白价，前端预估和后端结算用的是同一套规则，不存在「页面显示一个价、付款扣另一个价」。

数据要求：讲清楚差额（黑白 0.3 元/页、彩色 0.8 元/页），让评委听得出这次修复省了多少钱。

### 2:20–2:40　中段之四：隐私打码

画面：拖入含手机号的文档，敏感信息高亮，一键打码后预览。

口播：敏感信息在本地识别，不上传第三方；扫描件没有文字层时，页面会如实说「做不到」，不会假装通过。

### 2:40–3:20　高潮：交付证据（硬件）

画面顺序严格固定：

1. 切到 T5 屏，屏幕从「打印中」进入取件态，显示大号取件码
2. 手指点屏确认，屏幕回写「已确认」
3. 手机端订单详情刷新为「已取件」，显示取件时间与序号
4. 订单详情里出现 X5 抓拍的出纸现场照片

口播：取件码只在用户端出现，不印在纸上；点击确认是幂等的，重复点不会重复记录，乱序取件会触发告警。出纸有照片、取件有时间，交付从口头承诺变成可回看的证据。

要点：讲「证据」，不讲「我们做了块屏幕」。屏幕只是把证据搬到现场。

### 3:20–3:40　收尾：删得干净

画面：管理端「文件删除记录」，滚动出真实记录（截图内 39 条），原因列涵盖用户主动删除、打印完成 5 分钟、15 分钟未活跃、服务启动清理。

口播：源文件不会长期留在服务器和打印终端，每一次删除都有记录。最后如实说一句：真实短信、自动分账、支付宝当面付还没接，页面上标的是「待做」，我们没把它算成已完成。

## 三、录制前 10 分钟准备

| 项 | 检查动作 | 通过标准 |
| --- | --- | --- |
| 后端 | 线上 `https://silnk.cn`，或本地 `python -m uvicorn main:app --host 127.0.0.1 --port 8000` | 首页与 `/api/info` 均 200 |
| 短信 | `$env:SMS_DEMO_MODE = "1"`（本地时） | 页面明确标注「演示验证码」 |
| 打印机 | 打印客户端已连 silnk.cn，心跳正常 | 管理端设备页「在线」、纸量有数 |
| T5 屏 | COM 口已识别，桥接指向 `https://silnk.cn`，`--device printer-001` | 屏幕显示「在线」，不是「等待连接」 |
| X5 | 摄像头对准出纸托盘，**空托盘状态下重建基准** | 手伸入托盘能被识别，桌面与线材不误触 |
| 样例文件 | 12 页含 3 页彩色的 PDF、含手机号的文档 | 能直接拖进上传区 |
| 录屏 | 1080p / 30fps，窗口 1440×900，浏览器缩放 110% | 文字清晰可读 |

## 四、三条降级路线

1. **打印机临时罢工**：只演到支付与取件码，用管理端订单状态代替出纸画面，口播如实说明「打印机今天不可用」，不剪假镜头。
2. **T5 串口掉线**：屏幕会置灰显示「离线」并保留最后内容——这本身就是可演示的容错设计，直接讲出来。
3. **X5 误触发**：先重建空托盘基准再录，不要在基准未重建时硬录。

## 五、录制纪律

- 一段录到底，不拼接、不加伪造状态的演示字幕。
- 画面里出现的数字（纸量、金额、队列、得分、删除条数）必须是真实读出来的。
- 讲不清的功能不演；未接入的能力如果出现在画面里，必须口播「这是待做」。
- 每个画面都要有可见的数字或状态变化，静止的截图对路演没有说服力。
- 结尾不喊口号，停在能力清单即可。
